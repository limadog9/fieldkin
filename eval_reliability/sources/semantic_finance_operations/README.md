Independent source-only held-out financial schema packet, authored without reading matcher implementation, predictions, proposed changes, previous case labels or implementation-agent materials. No matcher or runtime evaluation was performed.

The selection and annotation rules were frozen in CRITERIA.json before field extraction. CRITERIA.sha256 records that initial rule snapshot. Sources are official CFPB and Adyen repositories pinned to immutable commits. PROVENANCE.json records exact original URLs, retrieval timestamps, repository licenses, original-file hashes and retained-artifact hashes. Raw material totals approximately 116 KB; Adyen files are exact JSON selections and reserializations of the complete PaymentRequest definitions, with all root properties preserved.

There are two cases: CFPB 2017 to 2018 Modified LAR (17 source fields, 25 target fields), and Adyen classic Payment API v52 to Checkout API v72 PaymentRequest (21 source fields, 26 target fields). Cases use the requested standard fields and answer format. Every included source field has a label and evidence entry. The selected target schemas include genuine competing financial roles. Answer labels identify semantic schema correspondence; they do not claim that changed code domains, units or representations support a lossless value migration.

Publisher metadata in context.json is extracted directly from selected fields, filing specifications, dictionaries and codesheets before answer construction. It contains raw descriptions, table/resource/schema names, schema paths, publisher type declarations, units/roles where expressly stated, version information, and citations. No description or role was invented from the answer crosswalk. Missing units or periods remain empty. Actual publisher examples appear in samples with their source citations; other fields are marked schema_only. Valid-value lists are preserved as metadata, not fabricated observation samples. No operational payment or borrower records are present.

The CFPB 2017 CSV dictionary is authoritative for the selected names/types, including character-varying Loan Amount; its parallel Markdown dictionary differs. The 2018 codesheet has a questionable loan-purpose code-31 description, so Loan Purpose was excluded. Income, ambiguous occupancy/property decompositions, respondent identifiers and geographic conversions were also excluded. The retained loan-amount correspondence requires conversion from thousands and accounts for the target dollar midpoint disclosure rule. The unmatched agency and metropolitan-area fields have roles absent from the complete 2018 Modified LAR dictionary.

The Adyen case selects documented top-level scalar properties. Known nested funding-source/stored-detail counterparts were excluded. Its two negatives distinguish report-total aggregation and account-updater control from nearby store/order-reference and payment-storage/authentication roles. Nationality was excluded because the target country-code description does not independently establish a different role. An official deprecation message and identical definitions establish two permissible delivery-date targets, including the preferred renamed target. Both are retained as a documented ambiguous label. The publisher has an inconsistent date-of-birth declared format across these APIs; the original declaration is preserved.
